# 2026-08-11: Farhan's flow, auth, and storage feedback, decisions locked in

## What this is

Real feedback from Farhan, reviewing the app as it stands, covering navigation, sign-out behavior,
token persistence, storage, and MFA. No code changed today, this was a decisions-and-documentation
session: the requirements were ambiguous enough in a few places that guessing wrong would have meant

## The requirements, as given

1. Sign-out should clear the app's own session only. It must **not** sign the user out of their
   Microsoft account, MSAL's `logoutRedirect()`/`logoutPopup()` are the wrong calls here, they hit
   Microsoft's own logout endpoint. The app should "forget about it," Microsoft shouldn't.
2. Token persistence: a hard refresh (F5) should not force a fresh login if the session is still
   valid, but the token's real expiry has to actually be honored, not silently extended forever.
3. Navigation is a strict tunnel. After signing in, a user sees **only** a project list, no other
   navigation. Pick or create a project, next is **model selection**, not a project overview. After
   a model is chosen, next is **dataset upload**, not an "Experiment" screen. No sideways or
   skip-ahead navigation is allowed anywhere in that sequence.
4. Storage: dataset files go to **Cloudflare R2** for now, not Azure Blob Storage. Metadata stays in
   Postgres either way. This was already anticipated as the Dev-stage stand-in when `CMP-38` was
   scoped, today's feedback confirms it's the real plan, not just an option.
5. Add multi-factor auth.

## Three real ambiguities, resolved with Anas before writing anything down

1. **MFA: native Entra, not a custom build.** The screenshot Farhan sent (a "Check your email,
   6-digit code" screen) looked like a custom email-OTP flow to build, but it's actually a reference
   screenshot from an existing product (cassandra.app, confirmed by Anas). The real decision: enable
   **Microsoft Entra's own MFA** (Security Defaults or Conditional Access) on the tenant, no app code
   at all. Microsoft's own hosted sign-in UI shows the prompt. Per [[mmm-jira-backlog]], **Anas does
   not have Entra tenant-admin rights, Farhan does**. This is Farhan's action item, not a ticket for
   Anas or Amna.
2. **Model selection stays a simple picklist, not a new module.** Anas pointed at cassandra.app as
   the UX reference. Its marketing site doesn't expose the actual in-app flow (it's behind a signup
   wall), so the concrete screen design is still open. For now: a fixed list of model type options,
   the choice stored as a field on the project or the dataset it precedes, no new database table, no
   new backend module. Revisit if the real product needs more than that.
3. **Session persistence: survive a hard refresh, but really expire.** Confirmed reading of Farhan's
   mixed Urdu-English note. This is an MSAL cache configuration question
   (`cacheLocation`, silent token renewal), not a backend concern, the backend is stateless and
   already re-validates every request's token against Microsoft regardless of how long the frontend
   holds onto it.

## Real OTP module built

A dedicated Entra app registration was created for this, separate from the sign-in app on purpose
(a confidential-client secret has no business living on the same registration a public SPA signs
in through): **"MMM Platform - Transactional Mail"**, single-tenant, Client ID
`e6e7e14d-a031-43cc-9254-c835ffe48040`, with the `Mail.Send` Application permission requested
(admin consent still needs Farhan's one click, everything else here doesn't). Sends from Anas's own
mailbox, `muhammad.anas.quershi@convergentbt.com`, for now.

Built and compiling clean:
- `otp_codes` table (migration `1785900000005`), same RLS/tenant-isolation shape as every other
  table. Stores only a SHA-256 hash of the code, never the code itself.
- `GraphMailService`: a direct `fetch()` call against Graph's `sendMail` REST endpoint using the new
  app registration's own client-credentials token, not the full Graph SDK, same reasoning as
  `EntraJwtVerifier` choosing `jose` directly over a heavier library.
- `OtpService`: generates a real 6-digit code, 10-minute expiry, 5-attempt limit, one-time use
  (`consumedAt` blocks replay).
- `POST /auth/otp/request` and `POST /auth/otp/verify`, both real authenticated routes (require a
  valid Entra sign-in first, this is a second factor layered on top, not a replacement).
- `OtpVerifiedInterceptor`: built as an Interceptor, not a Guard, on purpose, Guards run before
  Interceptors, so a Guard would fire before `TenantContextInterceptor` opens the tenant-scoped
  database session this needs. **Not applied to any route yet**, Amna's frontend has no code-entry
  screen built, gating real routes behind this now would strand every signed-in user with no UI to
  get past it.
- Local `.env` updated with the real credentials, `.env` is git-ignored, nothing committed.

App boots clean with everything wired in, verified with a real local run.
