## Two real problems hit and fixed, both now folded into `TEAM-GUIDE.html`

1. **Build failed: `sh: 1: nest: not found`.** Root cause: setting
   `NODE_ENV=production` as an environment variable makes `npm install`
   skip `devDependencies`, and `@nestjs/cli` (the `nest build` command)
   lives there, not in `dependencies`. Confirmed by reading
   `package.json` directly rather than guessing. Fixed by changing the
   Build Command to `npm install --include=dev && npm run build`.
2. **Boot refused: `AUTH_DEV_BYPASS=true with NODE_ENV=production. This
   would let every request into the API unauthenticated. Refusing to
   start.`** This is the app's own deliberate safety check
   (`main.ts`/env validation), working exactly as designed, not a bug.
   Anas asked directly why it wasn't just letting login through, real
   Entra login already being fully proven (`TC-04`) meant the right
   answer was to use it, not bypass the check: set
   `AUTH_DEV_BYPASS=false` for real on this deployment.
3. A third, expected failure in between: `password authentication
   failed for user "mmm_app"`, because that role only gets created by
   the `CreateAppRole` migration, which hadn't run against this
   database yet. Not a new bug, the exact thing `deployment-guide.html`
   already documented needing to happen.
