02Authentication

Every route requires a valid bearer token except GET /health. There is no API key and no session cookie, authentication is exclusively a real Microsoft Entra ID access token.

Value
Client IDfa733969-d53d-46ed-81fc-119c740a5cc9
Tenant IDd5619769-1863-41fe-86e3-95000d84f2a6
Scopeapi://fa733969-d53d-46ed-81fc-119c740a5cc9/access_as_user
HeaderAuthorization: Bearer <token>

Authorization Code + PKCE flow, no client secret, this is a public client (both the Postman collection and the real frontend use it this way).

First login provisions the account automatically

The first successful authenticated request from any real Microsoft account creates a tenant and user record if none exists yet. No invite, no separate signup call. Everyone signing in from the same company (@convergentbt.com) lands in one shared tenant. The first user provisioned into a brand-new tenant is automatically given the administrator role.

03Error format and status codes

Every error, from every endpoint, comes back in this exact shape:

{
  "statusCode": 404,
  "message": "Project 1f32fa3b-1fef-4b06-8fc0-1d8eeb35d0a3 not found.",
  "path": "/api/v1/projects/1f32fa3b-1fef-4b06-8fc0-1d8eeb35d0a3",
  "timestamp": "2026-08-07T10:18:26.902Z"
}

message is a plain string for most errors, or an array of strings for validation failures (multiple invalid fields listed together). Handle both shapes.

200 success 201 created 204 success, no body 400 malformed input 401 missing/invalid token 403 not allowed 404 doesn't exist or isn't yours
Row-Level Security means 404, not 403, across tenants

A project belonging to another tenant returns 404, not 403. There is no way to tell "doesn't exist" apart from "not yours" from the response, that's intentional, not an oversight.

05GET /auth/me

GET/auth/me

Returns what the token resolved to, and this platform's own internal ids. The right first call to make when debugging any connection issue, if this fails, nothing else will work either.

{
  "oid": "the Entra object id",
  "tid": "the Entra tenant id that issued the token",
  "email": "the signed-in user's email",
  "name": "the signed-in user's display name",
  "devBypass": false,
  "tenantId": "this platform's own tenant id (uuid)",
  "userId": "this platform's own user id (uuid)"
}

06Projects

The only real business entity implemented so far. Every route below requires auth and is automatically scoped to the caller's own tenant, enforced by the database itself (Row-Level Security), not just application code.

POST/projects

Creates a project owned by the signed-in user, in their own tenant.

Request body

FieldTypeRequiredConstraints
namestringyes1 to 200 characters
descriptionstringnoup to 2000 characters

Any field not in this list is rejected with 400, unknown fields are never silently ignored. status cannot be set on create, every new project starts "active".

Response, 201: the full project object, see the data model below.

GET/projects

Lists every project in the signed-in user's tenant. No pagination, filtering, or sorting yet, this returns the full list every time. Response is an array, possibly empty ([]).

GET/projects/:id

Returns one project by id.

CaseResponse
Malformed id (not a valid UUID)400
Well-formed id that doesn't exist, or belongs to another tenant404
Otherwise200, the project object

PATCH/projects/:id

Partial update. Only send the fields actually changing, fields you don't send are left completely untouched (a real bug where omitted fields used to get wiped to null was found and fixed August 6, this is safe to rely on now).

Request body, any subset of:

FieldTypeConstraints
namestring1 to 200 characters
descriptionstringup to 2000 characters
statusstring"active" or "archived"

Only the project's owner may update it. Anyone else, even in the same tenant, gets 403, "Only the project owner can do this."

Response, 200: the full, updated project object.

DELETE/projects/:id

Soft delete. The row is not removed from the database, deletedAt gets set. A deleted project no longer appears in GET /projects, and GET /projects/:id returns 404 for it afterward. Same ownership rule as PATCH, non-owners get 403. Response, 204, no body.

08Not built yet

09Multi-tenancy

  • Every real user belongs to exactly one tenant, resolved automatically from their Microsoft account on first login.
  • Tenant isolation is enforced at the database level, Postgres Row-Level Security, not just filtered in application code. Directly tested, not assumed: a query with no tenant context set returns zero rows even for an admin database account, fails closed, not open.
