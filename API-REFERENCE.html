02Authentication

Every route requires a valid bearer token except GET /health. There is no API key and no session cookie, authentication is exclusively a real Microsoft Entra ID access token.

Value
Client IDfa733969-d53d-46ed-81fc-119c740a5cc9
Tenant IDd5619769-1863-41fe-86e3-95000d84f2a6
Scopeapi://fa733969-d53d-46ed-81fc-119c740a5cc9/access_as_user
HeaderAuthorization: Bearer <token>

Authorization Code + PKCE flow, no client secret, this is a public client (both the Postman collection and the real frontend use it this way).

First login provisions the account automatically

The first successful authenticated request from any real Microsoft account creates a tenant and user record if none exists yet. No invite, no separate signup call. Everyone signing in from the same company (@convergentbt.com) lands in one shared tenant. The first user provisioned into a brand-new tenant is automatically given the administrator role.

03Getting a real token

For anyone testing the API directly, outside of a real signed-in frontend session. This is exactly how TC-04 in the backend's own test suite gets verified.

Postman

  1. Import the collection and environment from Backend/postman/ (or ask for a copy if you don't have access to the repo).
  2. Open the collection's own Authorization tab (not an individual request's), Type should be OAuth 2.0.
  3. Confirm the environment's tenantId, clientId, and scope match the values in Section 02 above, in both the Initial Value and Current Value columns.
  4. Client Authentication must be set to Send client credentials in body, not Basic Auth header, this app has no client secret (PKCE, public client).
  5. Click Get New Access Token. A real Microsoft sign-in window opens, sign in with a real @convergentbt.com account. First time, expect a consent screen, that's individual user consent, nothing that needs an admin.
  6. Click Use Token once it comes back. Any request in the collection now carries a real Authorization header.

Anything else (curl, a script, another tool)

Run the Authorization Code + PKCE flow yourself against https://login.microsoftonline.com/d5619769-1863-41fe-86e3-95000d84f2a6/oauth2/v2.0/authorize, using the Client ID and scope from Section 02. Once you have a token, calling the API is a plain bearer-token request:

curl https://mmm-back-end-anas.onrender.com/api/v1/auth/me \
  -H "Authorization: Bearer <your real token>"

04Headers, CORS, and response conventions

DirectionHeaderWhen
RequestAuthorization: Bearer <token>Every route except GET /health
RequestContent-Type: application/jsonAny request with a body (POST, PATCH)
ResponseContent-Type: application/json; charset=utf-8Every response, success or error

No other custom headers are set on either side. No rate-limit headers, no pagination headers, nothing beyond the standard ones a browser or HTTP client adds automatically.

  • CORS is wide open right now, any origin is allowed. Nothing needed on any client's side for this specifically.
  • Successful responses return the resource directly as JSON, no wrapper object, no { "data": ... } envelope.

05Error format and status codes

Every error, from every endpoint, comes back in this exact shape:

{
  "statusCode": 404,
  "message": "Project 1f32fa3b-1fef-4b06-8fc0-1d8eeb35d0a3 not found.",
  "path": "/api/v1/projects/1f32fa3b-1fef-4b06-8fc0-1d8eeb35d0a3",
  "timestamp": "2026-08-07T10:18:26.902Z"
}

message is a plain string for most errors, or an array of strings for validation failures (multiple invalid fields listed together). Handle both shapes.

200 success 201 created 204 success, no body 400 malformed input 401 missing/invalid token 403 not allowed 404 doesn't exist or isn't yours
Row-Level Security means 404, not 403, across tenants

A project belonging to another tenant returns 404, not 403. There is no way to tell "doesn't exist" apart from "not yours" from the response, that's intentional, not an oversight.

08Projects

The only real business entity implemented so far. Every route below requires auth and is automatically scoped to the caller's own tenant, enforced by the database itself (Row-Level Security), not just application code.

POST/projects

Request body

FieldTypeRequiredConstraints

PATCH/projects/:id

Partial update. Only send the fields actually changing, fields you don't send are left completely untouched (a real bug where omitted fields used to get wiped to null was found and fixed August 6, this is safe to rely on now).

Request body, any subset of:

FieldTypeConstraints
namestring1 to 200 characters
descriptionstringup to 2000 characters
statusstring"active" or "archived"

Request example, renaming only, description is deliberately absent and will not be touched:

curl -X PATCH https://mmm-back-end-anas.onrender.com/api/v1/projects/1f32fa3b-1fef-4b06-8fc0-1d8eeb35d0a3 \
  -H "Authorization: Bearer <your real token>" \
  -H "Content-Type: application/json" \
  -d '{"name":"Q4 Brand Campaign (renamed)"}'

Response, 200, note description is unchanged, and updatedAt moved:

{
  "id": "1f32fa3b-1fef-4b06-8fc0-1d8eeb35d0a3",
  "createdAt": "2026-08-06T11:51:35.322Z",
  "updatedAt": "2026-08-06T12:03:11.837Z",
  "tenantId": "c7d1d3f5-673f-428d-9f89-3125df7d4eb2",
  "name": "Q4 Brand Campaign (renamed)",
  "description": "First real project",
  "ownerId": "6d3f500e-acaf-4f21-a9b5-30621a8f34bc",
  "status": "active",
  "deletedAt": null
}

Only the project's owner may update it. Anyone else, even in the same tenant, gets 403:

{
  "statusCode": 403,
  "message": "Only the project owner can do this.",
  "path": "/api/v1/projects/1f32fa3b-1fef-4b06-8fc0-1d8eeb35d0a3",
  "timestamp": "2026-08-10T07:59:48.602Z"
}

DELETE/projects/:id

Soft delete. The row is not removed from the database, deletedAt gets set. A deleted project no longer appears in GET /projects, and GET /projects/:id returns 404 for it afterward. Same ownership rule as PATCH, non-owners get 403.

curl -X DELETE https://mmm-back-end-anas.onrender.com/api/v1/projects/1f32fa3b-1fef-4b06-8fc0-1d8eeb35d0a3 \
  -H "Authorization: Bearer <your real token>"

Response, 204, empty body, that's normal for a 204, there's nothing to show.

09Datasets & model configuration (CMP-38, CMP-79)

Everything below is real and live, not a plan. All routes require auth and are scoped to the caller's own tenant, same as Projects. A dataset is one model-in-progress: upload the file, then Configure, Optimize, Calibrate and Hyperparameterization each save one real piece onto the same dataset row.

POST/projects/:projectId/datasets

Uploads a real file (multipart form-data: name, modelType, file), stored in Cloudflare R2. Rejects the file (400) before it ever reaches storage if its extension isn't .csv/.xlsx/.parquet, or its actual bytes don't match that extension (a renamed file doesn't get through). On success, the row's status is "validated".

curl -X POST https://mmm-back-end-anas.onrender.com/api/v1/projects/<projectId>/datasets \
  -H "Authorization: Bearer <your real token>" \
  -F "name=Real Test Dataset" -F "modelType=meridian" -F "file=@sample-dataset.csv"

Response, 201

  "id": "d9a0b0e8-98a4-4d6c-b8c8-2e268ea4d6b6",

PATCH/datasets/:id/configuration

The Configure step, matching Hammad's column_mapping + kpi_type + revenue_per_kpi_value exactly.

FieldTypeNotes
dateColumn, targetColumnstringrequired
kpiTypestring"revenue" or "non_revenue"
revenuePerKpiValuenumberrequired if kpiType is non_revenue, must be absent if revenue, 400 either way if violated
mediaColumnsstring[]at least one
controlColumnsstring[]can be empty
organicColumns, geoColumnsstring[]optional

400 if the same column name is reused across date/target/media/control/organic/geo.

PATCH/datasets/:id/optimize

Body: { startDate, endDate }, real ISO dates. 400 if startDate isn't before endDate.

PATCH/datasets/:id/calibration

Body: { contributionBeliefPercent, confidencePercent }, both 0 to 100.

PATCH/datasets/:id/hyperparameters

Body: { channels: [{ channel, carryover, saturation }] }. Requires Configure already saved, and the channel list must exactly match Configure's mediaColumns, no more, no fewer, 400 naming exactly what's missing or unexpected otherwise. carryover is 0 to 1, saturation is 0 or above.

POST/datasets/:id/assemble

Requires Configure, Optimize, Calibrate and Hyperparameterization all saved (400 naming which is missing otherwise). Builds the one real JSON file Hammad's contract needs, saves it to R2, generates a real job_id. Sends nothing to Hammad's worker, there's nowhere stable to send it yet, see Section 11.

Response, 201

GET/samples/dataset.csv

@Public(), no auth needed. A real 16-week sample CSV, in the exact column shape Hammad's model expects, for the "Download sample dataset" link.

Train Model: mock, real shape, decided 2026-08-12

Real training against Hammad's worker is on hold, blocked on decisions still with Farhan (auth, and what to build against given Colab/ngrok's real instability). Rather than leave Train Model disabled, it runs a real mock: same real endpoints below, same real result shape as Hammad's own sample output (Resources/Handover MMM - Hammad/Model Integration Original/final_results.json), computed from the real uploaded data and real hyperparameters, not random numbers. Every result carries results.mock: true and its own data-quality flag saying so. Swapping this for a real trained result later is a data-source change, not a rebuild.

POST/datasets/:id/train

Requires the same four steps as /assemble (Configure through Hyperparameterization). Assembles the real job file, then generates a mock result and starts an 8-second fake "running" window. No queue, no worker, nothing sent anywhere.

Response, 200, the dataset row, note trainingStatus and trainingStartedAt:

{ "id": "...", "trainingStatus": "running", "trainingStartedAt": "2026-08-12T10:00:00.000Z",
  "jobId": "...", "results": { "...": "the full mock result, see GET /results below" } }

GET/datasets/:id/status

Polls the mock run. status is "running" for about 8 seconds after POST /train, computed fresh from elapsed time on every call, not a stored value, then "completed".

{ "status": "running", "progress": 0.42, "jobId": "3f2a1c9e-..." }

GET/datasets/:id/results

400 if training hasn't started or is still running. Once "completed", the full real-shaped mock result: data_used, model_confidence, channel_contribution, channel_efficiency, data_quality_flags, budget_recommendation, saturation_status, adstock_decay_curves, saturation_curves, exactly the shape and field names of Hammad's own sample output.

10Email code second factor (OTP)

A real second factor, not Entra's own MFA (see dev-log/for-anas/modeling-engine-explained.html's sibling docs for why). A 6-digit code, SHA-256 hashed, never stored plaintext, 10-minute expiry, 5-attempt lockout.

POST/auth/otp/request

Sends a real code to the signed-in user's real inbox via Microsoft Graph. 202 on success.

POST/auth/otp/verify

Body: { code }. 204 on a correct code, 401 ("Incorrect code.") on a wrong one, same for expired, and after 5 wrong attempts ("Too many incorrect attempts").

What's still missing is only the send, not the assembly. Full trace in dev-log/for-anas/modeling-engine-explained.html Section 03.

13Multi-tenancy

  • Every real user belongs to exactly one tenant, resolved automatically from their Microsoft account on first login.
  • Tenant isolation is enforced at the database level, Postgres Row-Level Security, not just filtered in application code. Directly tested, not assumed: a query with no tenant context set returns zero rows even for an admin database account, fails closed, not open.
