01The frontend

Angular SPA, deployed on Vercel

The user-facing app. Signs in with a real Microsoft account through MSAL, using a redirect flow (not a popup, that failed in testing due to a cross-window communication issue common on modern hosts). Every API call carries the real token automatically, via an interceptor, existing service code (project.service.ts and similar) never has to handle the token itself.

Every push to its own repository redeploys automatically. See TEAM-GUIDE.html Section 5 for the deployment steps.

02Authentication

Microsoft Entra ID, not a homegrown login

A single-tenant Entra app registration, Authorization Code plus PKCE, no client secret. First sign-in from any real Microsoft account auto-provisions a tenant and user on the backend, no invite step. See API-REFERENCE.html Section 02 for the real Client ID, Tenant ID, and scope.

03The backend

NestJS, deployed on Render

Owns tenancy, auth, and the platform's business data. It never fits a model itself, that's a separate process by design, real modeling runs take minutes to hours and cannot happen inside an HTTP request.

Live now: the Auth Guard and Tenant Interceptor (validates every token, resolves it to a real tenant and user, enforces Row-Level Security context), and the Projects module, full CRUD, owner-only edit and delete.

Not built yet: Datasets, Experiments, and Jobs. See API-REFERENCE.html Section 10 for the exact routes that will 404 until these exist.

04The database

Postgres, deployed on Render

Multi-tenant by row, not by separate database per customer. Every tenant-owned table enforces Row-Level Security with FORCE, meaning the rule applies even to the admin database role, not just application code. Directly tested, not assumed, see Trainings/NestJS/knowledge-base/lessons/06-locked-out-by-your-own-rule.html for a real case where this caught the very people who built it.

05Not built yet

Real, on the roadmap, drawn dashed above on purpose

Blob Storage holds the actual uploaded dataset files, Postgres never stores the raw file, only metadata pointing at it. Job Queue and the Python Modeling Worker are how a model run actually happens, decoupled from the request that starts it, so the backend can answer immediately with a job id instead of the caller waiting minutes to hours for a response. CMP-79 defines the exact message contract between the backend and the worker before either side builds against it.
